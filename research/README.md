# 研究：面向多 Agent 的用例库扩展（2026-06）

本目录是 **Part 2 — 深度研究** 的交付物：为「把仓库从 OpenClaw 用例库升级为**面向多 Agent、跨垂直领域的领域最佳用例库**」提供决策输入。

> ⚠️ **这些是候选与分析，不是收录。** 所有候选都由多 Agent 工作流搜罗 + 对抗式核验 + 去重产出，但**没有一个由本仓库维护者亲自跑通**。按 [CONTRIBUTING.md](../CONTRIBUTING.md) 的红线（真实跑通 + 多源验证 + 可复现），任何候选都需**先验证一次真实运行**，才可写成 `usecases/*.md` 入库。本目录刻意如实标注每个候选的证据强度，不夸大。
>
> 本研究与 **Part 1（PR #94：to-agent 适配层 + 人机分工协议，引入 `AGENTS.md`）** 配套；下文提到的 `AGENTS.md` / `INDEX.md` / `CONCEPT-MAPPING.md` 由 PR #94 引入，合并后即可在根目录查阅。

## 怎么产生的

- **16 条赛道并行搜罗**：12 个垂直领域（法律 / 医疗 / 财税 / 电商 / 营销 / DevOps / 科研 / 客服 / HR / 地产 / 教育 / 供应链）+ 4 条旗舰挖掘（Claude Code / Codex / Hermes & 框架 / OpenClaw 近月新例）。
- **逐候选对抗式筛查**：每个候选独立核验「是否有真实用户端到端跑通」「是否与现有 50 个重复」「是否过收录红线」。
- **结果**：73 个候选 → 30 个过筛存活 → 精选出 Tier A（真实用户已验证）/ Tier B（待验证）。

## 最该优先的方向（一句话结论）

1. **填补零覆盖垂直**：法律、专业医疗、财税记账、HR、地产、营销/SEO、教育、Agent 安全——现有 50 个用例**完全没有**。这些是把库带出「OpenClaw 范畴」、走向垂直专业的最大增量。
2. **证据最硬、可立即起草（Tier A，单一实名实践者 + 完整跑通 + 具体产物）**：`A3 hledger 记账`、`A6 Amazon FBA 日常运营（有美元 ROI 截图）`、`A9 CI 看护`、`A11 计量经济复现审计`、`A13 代码库支撑的客服`、`A15 商业地产租约`、`A16 代码库转课程`、`A17 Bun→Rust 单会话扇出迁移`、`A19 OpenAI 自家 OSS 维护即技能`。
3. **反向适配最干净、最该 port**：`B/A18 隔夜自愈循环`（几乎一一映射 OpenClaw 原语）、`G/A19 维护即 skills`。
4. **明确不做**：真钱金融、纯营销不可复现案例、商业 SaaS 正文推荐、未实现的 aspirational 概念。

## 下一步建议

1. 你从 Tier A 圈定 3–5 个想做的（建议先挑零覆盖垂直里证据最硬的）。
2. 对每个：你或我**实际跑通一次**（或确认你已跑通），补足"真实跑通"证据。
3. 验证后再写成 `usecases/*.md`——并直接套用 Part 1 的「👤 人机分工」块约定（见 `AGENTS.md` 人机分工协议，PR #94 引入）。这样 Part 1 的协议与 Part 2 的新用例就闭环了。
4. 定位若采纳，按 POSITIONING 的 R2/R3 给旗舰用例试点 frontmatter + 自动生成 `index.json`，把「领域最佳用例 API 接入点」落到实处。
